# BP to Sheets · USB 웹 설정

설치 없이 USB로 Waveshare ESP32-S3 LCD 비터치 보드의 HEM-7155T / Microlife BP B4 BT를 설정한다. 기존 ESP32-C3의 기본 설정도 유지한다.

**접속 주소: https://djkoolcat.github.io/bp-to-sheets-web/**

## 사용 방법

1. Windows·Mac의 Chrome 또는 Edge에서 위 주소의 **처음 설정 안내**를 연다.
2. 본인의 비공개 시트 주소를 입력하고 Apps Script 수신기를 준비한다. 필요한
   `Code.gs`·`appsscript.json`과 Google 화면의 붙여넣기 위치를 안내한다.
3. 데이터 USB 케이블로 연결하고 **USB 보드 선택**으로 보드 ID·혈압계 관리 ID를 확인한다.
4. 기기 토큰을 만들고 Google 스크립트 속성에 직접 등록한다. 기존 기기 목록은 유지해 병합한다.
   보드에 저장된 토큰을 유지하는 경로도 있다.
5. Google 초기화·배포 후 Wi-Fi·`/exec` URL을 USB로 저장하고 재연결·Google 연결 시험을 확인한다.
6. 혈압계 등록·수신 안내를 따른다. 저장된 키와 실제 수신 완료는 별개로 표시한다.
7. 사용자 1·2 탭 주소를 보드에 저장한다. 웹에서 각 사용자 시트를 열 수 있고,
   S3 LCD 메뉴 ‘기록 시트’에서 사용자별 QR을 표시한다.

기존 사용자는 **설정·기록 관리**로 바로 이동한다. 단계 이름을 눌러 설명을 미리
볼 수 있지만, 이동만으로 완료 처리하지 않는다. Google 계정 승인·속성 저장·배포는
Google 화면에서 직접 진행한다. 시트 공유 권한을 공개할 필요는 없다.

이미 저장된 비밀번호·토큰은 빈칸이면 유지된다. 처음 설정할 때는 본인의 비공개
Google 시트와 Apps Script 수신기 및 기기 인증을 먼저 준비해야 한다.
사이트 방문에는 GitHub·ChatGPT 로그인이 필요하지 않다.

## 기능과 보존

- 보드 버전·전송 대기/보관 건수·Wi-Fi·Google 연결·동작 로그를 확인한다.
- 보드·혈압계 식별자와 응답을 검증한 뒤 설정을 허용한다.
- 비밀번호·토큰은 USB로 보드에만 전달하며 웹 서버나 브라우저 저장소에 저장하지 않는다.
- 저장 확인 응답을 받은 뒤 성공을 표시하고 비밀번호·토큰 입력을 비운다.
- 응답이 유실돼도 설정 저장·연결 시험을 자동 재실행하지 않는다.
- USB 단절 뒤 이전에 허용한 같은 보드의 상태·로그 읽기를 재개한다. 직접 연결 해제하면 자동 재연결을 중단한다.
- **기록 파일로 저장**에서 사용자 1·사용자 2·전체를 골라 CSV 또는 실제 `.xlsx` 파일을 PC에 저장한다.
  S3 `hem-0.7.0` 이상에서 지원한다. 엑셀 전체 저장은 사용자 1·사용자 2·전체 기록·안내 탭 순서다.
  보드가 보관 중인 최대 128건이 대상이며 혈압계/Google 시트의 전체 장기 이력과 다를 수 있다.
  Wi-Fi 없이도 사용한다. 읽는 도중 기록/저장 확인 상태가 바뀌거나 USB가 끊기면 완성 파일을 만들지 않는다.
  수신 일시는 보드에 별도로 보관하지 않아 빈칸이다. 암호·토큰·혈압계 인증 키·수신 URL·원시 통신은 파일에서 제외한다.
- 혈압계 원본 기록·시간·새 기록 카운터를 변경하지 않는다. 시트 공유 권한도 바꾸지 않는다.

현재 정식 웹·S3 배포는 1.0.0이다. Mac/S3의 기존 설정·일상 사용·업데이트가 확인된 범위이며, 새 통합 최초 설정·초기화 실제 삭제·Windows 실기기는 추가 확인 대상이다. 기존 USB 설정 연결에는 BP to Sheets 펌웨어가 필요하다. 새 S3 LCD의 최초 펌웨어 설치를 아래 웹 0.7 절차로 지원한다. Omron 최초 등록은 S3 hem-0.9.0 이상의 웹 마법사에서 지원하며, 실제 웹 최초 등록 성공 시험은 별도 빈 보드가 없어 보류 중이다. 보드 교체는 기존 혈압계 관리 ID 이전부터 진행해야 한다.
현재 S3 LCD 보드는 아래 웹 USB 업데이트를 이용한다. 별도 운영체제별 앱 설치는 필요 없다.
휴대폰·Safari·인앱 브라우저에서의 USB 연결은 지원 범위에 포함하지 않는다.
합성 USB 시험과 실제 하드웨어 시험은 구분한다. 2026-11-03 Mac과 S3 `hem-0.6.10`에서
실제 케이블 분리/재연결 뒤 상태와 새 부팅·Wi-Fi 로그가 자동으로 돌아오는 것을 확인했다.
Windows 실기기 실행은 별도로 남아 있다.
0.3의 합성 시험은 16개다. 실제 S3의 두 사용자 보관 기록을 Wi-Fi 미연결 상태에서 읽고,
CSV와 엑셀의 사용자·값·날짜 정밀도·ID·빈 수신 시각을 RAM에서 대조했다. 실제 개인 기록을
이 저장소나 시험 픽스처에 포함하지 않는다. Excel/Numbers 앱 자체의 표시 확인은 형식 검사와 구분한다.

0.4는 총 30개 합성 시험에서 토큰 발급·기존 등록 병합·보드 교체 시 비밀 값 제거·
Google 최종 확인·잘못된 링크 거부·QR 저장 ACK/보존·응답 유실 시 단일 쓰기를 확인한다.
실제 브라우저의 단계 이동·입력 잠금·빠른 관리 전환을 확인하며, 새 보드의 처음 설정
실기기 시험과 Google의 실제 신규 배포는 별도다. 사용자 요청으로 새 보드 시험은 보류했다.

토큰 생성은 명시적인 버튼 조작으로만 실행한다. 비밀번호·토큰·붙여넣은 기존 JSON은
현재 페이지 메모리에만 두며 페이지 종료 때 지운다. 다른 보드가 선택되면 기존 비밀
입력과 확인 상태를 지운다. 복사한 JSON에는 토큰이 있으므로 Google 속성에만 붙여넣고
클립보드는 사용 후 직접 비운다. 사용자 탭 주소는 같은 시트의 서로 다른 gid만 허용하고,
보드가 확인한 저장 값만 열기 링크에 사용한다. QR에는 토큰을 넣지 않는다.

## 개발·배포

Node.js 22 이상에서 다음을 실행한다. 외부 패키지 설치는 필요 없다.

```sh
npm run check
npm test
npm run dev
```

`main` 변경 시 GitHub Actions가 공개 파일 검사와 합성 USB 시험을 통과한 뒤
`dist/`의 정적 파일만 GitHub Pages에 게시한다. 주소 아래의 상대 경로를 사용하므로
별도 도메인·Cloudflare·상시 실행 서버가 필요하지 않다.

이 공개 저장소에는 설정 웹·합성 시험·비밀 값 없는 수신기 설치용 사본만 포함한다.
펌웨어·Apps Script·설치형 앱의 개발 원본은 별도의 비공개 저장소에서 관리한다.
수신기 사본은 Google 프로젝트에 붙여넣기 위한 일반 소스이며, 기기 토큰은 포함하지 않는다.
실제 비밀번호·토큰·수신 URL·
개인 시트 주소·측정 기록·플래시 백업을 커밋하거나 이슈에 올리지 않는다.


## 웹 0.5: Microlife·알림 소리

S3 `hem-0.8.0` 시험본에서 혈압계 종류 전환, 검색된 BP B4 BT 본인 기기 등록,
음량/음소거 저장과 비프·차임 시험을 지원한다. 전송 대기 중에는 종류를 전환하지 않으며,
전환 뒤 USB 보드를 다시 선택하고 새 관리 ID의 Google 등록을 확인한다.
기존 오므론 키·종류별 기록·시트 링크는 유지한다. BP B4 BT 실기기에서 두 사용자 새 측정의
자동 수신·LCD 일치·Google 저장과 전원 차단 후 대기 기록 복구를 확인했다. 다른 모델에는 일반화하지 않는다.
서버 토큰이나 Wi-Fi 비밀번호를 이 사이트에 전송·저장하지 않는 정책은 유지한다.


## 웹 0.6: 버전 확인·USB 업데이트

Windows·Mac의 Chrome/Edge에서 설치형 앱 없이 현재/최신 버전을 비교하고 업데이트한다.
첫 배포 대상은 Waveshare ESP32-S3-LCD-1.54 비터치이며 현재 동봉 버전은 `hem-1.0.0`이다.
C3는 기존 웹 설정·로그 기능을 유지하고 이 업데이트 버튼은 활성화하지 않는다.
출고 보드 최초 설치나 다른 S3 모델에 일반화하지 않는다.

1. USB 보드를 선택하고 ‘펌웨어 업데이트’에서 두 버전을 확인한다.
2. 새 버전이면 ‘USB로 업데이트’를 누른다. 같은 버전은 ‘같은 버전 다시 설치’를 직접 선택해야 한다.
   현재 보드가 배포본보다 새로우면 이전 버전으로 내리지 않는다. 입력 중인 설정은 먼저 저장하거나 지운다.
3. 페이지와 케이블을 유지한다. 파일·보드·기록 보관 확인 → 앱 기록 → 검증 → 재연결·보존 확인을 진행한다.
4. 중단되면 이 페이지의 ‘USB 다시 선택’으로 원래 보드를 고른다. 기록이 끝났다면 확인만 이어가고,
   쓰기 중단이면 사용자 조작 후에만 같은 검증 파일을 다시 기록한다. 페이지를 닫으면 RAM 비교 자료는 사라진다.

일반 앱 업데이트는 주소 0x10000만 기록하며 전체 지우기·파티션/부트로더 쓰기를 제공하지 않는다.
원래 앱에서 hold ACK를 받은 뒤 기록하고, ROM의 실제 칩/MAC·16MiB 플래시·정확한 파티션
구성과 MD5·앱 SHA-256을 검사한다. NVS·동작 로그의 쓰기 전후 해시는 RAM에서만 비교하고
원본 영역을 내려받거나 비밀정보·측정값을 파일에 저장하지 않는다. 보안 부팅/암호화 구성은 지원하지 않는다.
기록 후 실제 앱 버전·보드/혈압계 ID·Wi-Fi/토큰/키 존재·시트 링크·보관 건수를 대조한다.
기록 내보내기를 지원하던 펌웨어는 모든 보관 기록의 측정 필드와 ID도 RAM에서 비교하며 ACK 후퇴를 거부한다.

`connect-src 'none'`와 서버 전송 금지 정책을 유지한다. 배포 정보와 범용 앱 이미지는
같은 사이트의 JavaScript 모듈로 읽고, ESP32 NVS/플래시 백업을 이미지로 사용하지 않는다.
Espressif esptool-js 0.7.1·pako·atob-lite·Noble MD5를 고정 의존성으로 묶어 같은 사이트에 동봉한다.
MD5는 ESP32 프로토콜 및 보관 영역 불변 비교용이며 앱 파일의 신뢰 검사는 SHA-256이다.
CDN·fetch·브라우저 저장소·개인 수신 URL·토큰은 사용하지 않는다.

개발 원본에서 `npm ci` 후 `npm run build-flasher`로 공개 플래셔 번들을 생성한다.
범용 S3 빌드만 `npm run prepare-firmware -- /절대경로/s3-lcd154.ino.bin`으로 전달한다.
배포 목록의 칩·크기·SHA-256과 일치하지 않는 파일은 거부한다. 공개 저장소는 검토된
정적 모듈/라이선스만 미러링하며 개인 서버·시트 주소나 펌웨어 개발 원본은 공개하지 않는다.
`npm test`와 `npm run check`는 칩/파티션 거부·무재시도·복구 확인 전용 경로와 공개 파일 목록을 검사한다.


2026-11-04 macOS Chrome와 실제 S3 LCD에서 같은 `hem-0.8.3`을 웹으로 재설치했다.
파일 검증 → ROM/파티션 검사 → 앱 쓰기/MD5 검증 → 재시작/자동 재연결 → 보존 확인을 완료했고,
보관 45건·전송 대기 0건 및 모든 내보내기 측정 필드·ID·설정이 유지됐다.
NVS/로그 해시의 쓰기 전후 일치도 확인했다. Windows에서의 실제 USB 플래시는 별도 확인이 남아 있다.
실기기에서 기본 4KiB 읽기 패킷이 native USB 버퍼에서 중간에 끊겨, 파티션 표만 256바이트씩
윈도 1·누적 ACK·최종 MD5로 읽도록 제한했다. 리셋도 RTS assert/release를 명시해 앱으로 복귀한다.
개인 측정값이나 원시 플래시 내용은 시험 파일에 남기지 않았다.


## 웹 0.7: 새 S3 LCD 최초 설치

‘새 보드 최초 설치’는 BP to Sheets가 없고 보존할 자료가 없는 **Waveshare
ESP32-S3-LCD-1.54 비터치·16MB** 보드 전용이다. 컨트롤러에서 LCD 보드의 제품명까지
자동 판별할 수 없으므로 제품 확인은 사용자가 직접 한다. C3·터치 모델·다른 S3는 대상이 아니다.
사용 중인 보드는 분리하고 새 보드 하나만 연결한다. 기존 보드를 업데이트하려면 0.6의 앱 전용 업데이트를 쓴다.

1. 모델 및 ‘보존할 기록·설정이 없는 새 보드’ 확인란을 선택한다. 출고 데모는 교체될 수 있다.
2. ‘새 USB 보드 선택 · 설치 가능 확인’으로 USB 포트를 고른다. 아직 플래시에 쓰지 않는다.
3. 실제 S3/16MB/보안 구성을 확인하고, 파티션 표와 설정·로그 영역의 해시만 검사한다.
   기존 `hem-log` 파티션이 있거나 NVS/로그가 비어 있지 않으면 **기록하지 않고 중단**한다.
   출고 보드라도 제조사 데모가 NVS를 초기화했다면 중단할 수 있다. 강제 초기화는 제공하지 않는다.
4. 표시된 보드 ID를 확인하고 별도 설치 확인란을 선택한 뒤 ‘확인한 새 보드에 처음 설치’를 누른다.
5. 설치·검증·재시작 후 같은 보드의 버전과 보관/대기 0건, 미설정 상태가 확인되면
   ‘설정 마법사로 계속’으로 이동한다. 시트·Wi-Fi·혈압계 등록은 별도 설정 단계다.

범용 빌드의 SHA-256을 고정한 부트로더(0x0), 파티션 표(0x8000), 앱(0x10000)만 기록한다.
파일별 MD5 검증을 수행하며 NVS(0x9000~0xefff), PHY(0xf000), 동작 로그(0x610000~0x61ffff)를
지우거나 기록하지 않는다. 쓰기 직전에 물리 보드 ID와 빈 저장 영역을 다시 확인하고, 쓰기 전후
설정·로그 해시를 비교한다. ESP32 eFuse 쓰기·보안 설정 변경·전체 플래시 삭제·원본 플래시 백업은 없다.

설치가 중단되면 **페이지를 유지한 채 같은 보드를 수동으로 다시 선택**한다. 무인 재기록은 하지 않는다.
기록이 완료됐거나 케이블 재연결 후 세 파일이 정확히 일치하면 다시 쓰지 않고 앱 확인만 이어간다.
다른 보드로 바뀌었거나 저장 영역에 자료가 생겼으면 중단한다. 페이지를 닫아 비교 상태를 잃었거나
부분 설치 상태를 안전하게 판단할 수 없으면 개발자 점검이 필요하다. 설치 확인만 했다면 취소하여 원래 앱으로 재시작할 수 있다.

`npm run prepare-initial -- /절대경로/검증한-일반-빌드-폴더`는 고정 해시가 일치하는
`.ino.bootloader.bin`·`.ino.partitions.bin`만 공개 모듈로 만든다. 앱은 기존 일반 앱 모듈을 재사용한다.
실제 보드에서 추출한 바이너리, 개인 기록, Wi-Fi 비밀번호, 토큰을 사용하지 않는다.

2026-11-04: 합성 USB 및 실제 플래셔 옵션 경계 시험과 브라우저 확인을 수행했다.

## Google 준비 간소화 (웹 0.9.0)

펌웨어는 hem-0.9.0 그대로이며 현재 보드·수신기 설정을 바꿀 필요가 없습니다.
새로 선물받는 사람이 준비할 때 사용하는 흐름입니다.

1. 본인 계정의 비공개 Google 시트를 만들고, 그 시트의 **확장 프로그램 → Apps Script**를 엽니다.
2. 웹 1단계 **수신기 코드 복사**를 눌러 Code.gs 전체를 교체·저장하고 `setupReceiver`를 실행합니다.
   Google 요청 권한(계정의 시트 접근·트리거 관리·설정 창 표시)을 직접 검토·승인합니다.
   새 프로젝트의 기본 매니페스트는 권한을 자동 감지합니다. 명시적 매니페스트를 쓰는 고급 경로용 파일도 제공합니다.
3. USB 보드 확인 후 웹 3단계에서 토큰을 만들고 **Google 설정용 등록 값 복사**를 누릅니다.
   Google 시트의 **BP to Sheets → 처음 설정** 창에 한 번 붙여넣고 기기 등록·탭 준비를 실행합니다.
4. 설정 창은 기존 기기 등록과 기록을 유지하며 현재 시트 ID·병합한 인증 설정을 저장하고,
   사용자 1·사용자 2·전체 기록·기기상태·장애이력 탭과 상태 검사 트리거 하나를 준비합니다.
   같은 보드의 토큰/관리 ID 교체에는 별도 직접 확인이 필요합니다. 다른 시트에 연결된 속성과
   기존 사용자 지정 기록 탭, 호환되지 않는 데이터/수식이 있으면 덮어쓰지 않고 거절합니다.
5. Google 설정 창의 **준비 결과**를 웹에 붙여넣으면 같은 보드·관리 ID·시트·이번 설정 회차인지 검사하고
   사용자별 QR 링크를 입력란에 채웁니다. 준비 결과에는 토큰이 없고, 실제 연결 성공을 증명하지 않습니다.
   등록 확인란은 직접 선택하며 링크는 6단계에서 USB로 저장해야 적용됩니다.
6. Apps Script **웹 앱 배포**는 본인이 직접 진행합니다(실행: 나, 접근: 모든 사용자).
   시트 공유는 제한됨 유지. /exec URL과 Wi-Fi를 보드에 저장한 뒤 Google 연결 시험을 통과해야 통신 확인으로 표시합니다.

기존 독립 Apps Script 프로젝트는 고급 스크립트 속성 입력 경로를 유지합니다. 같은 시트에 수신기를 중복 배포하지 마세요.
설정 창은 시트에 연결된 편집기/메뉴에서만 열리며, 공개 GET/POST로 설정 변경·토큰 조회·설정 HTML 제공을 하지 않습니다.
브라우저 입력은 영구 저장하지 않고 서버로 전송하지 않습니다. Google에 토큰을 보내는 동작은 사용자가 자신의 Google 설정 창에서 직접 합니다.
소스/다운로드/클립보드 코드 동기화는 `node tools/prepare-receiver.mjs`로 검사·준비합니다.

이 Google 설정 창의 실제 계정 승인·편집기 실행·배포 동선은 별도 미검증입니다. 합성 스프레드시트/USB/DOM 검증과 구분합니다.
공식 근거: https://developers.google.com/apps-script/guides/dialogs 및 https://developers.google.com/apps-script/guides/html/communication
